# Routine App

PWA-чеклист утренней и вечерней рутины. Главная задача — показать, какое дело делать
прямо сейчас, чтобы не вспоминать порядок. Рассчитан на ежедневное использование с телефона.
Пет-проект для портфолио, разрабатывается с Claude Code.

Текущий план и бэклог — в `docs/ROADMAP.md`.

## Стек
- React + Vite + TypeScript
- vite-plugin-pwa (офлайн, установка на главный экран)
- CSS Modules, без UI-библиотек и CSS-фреймворков
- Vitest — тесты на чистую логику (время, очередь дел)
- ESLint + Prettier
- Деплой: GitHub Pages через GitHub Actions

## Доменные правила
- Логический день длится с 06:00 до 06:00. Дата дня = дата от (сейчас − 6 часов).
- Утро: 06:00–18:00, вечер: 18:00–06:00. Показывается только текущая рутина.
- Отметки сбрасываются в начале нового логического дня (06:00).
- Список дел хранится в localStorage (через `storage.ts`) и меняется в редакторе.
  `src/data/tasks.ts` — только стартовый список для первого запуска.
  Порядок в списке = порядок выполнения. Задачи с `enabled: false` не показываются.
- Изменения в редакторе сразу действуют на сегодняшнюю очередь, отметки сохраняются.
- Текущее дело = первое невыполненное в очереди. Оно показывается крупно, остальные мелко.
- «Готово» отмечает дело выполненным. «Сделаю позже» переносит его в конец очереди.
- Когда всё сделано, показывается экран «Всё готово».
- Поле `required` пока ни на что не влияет в UI, но хранится.

## Архитектура
- `src/data/tasks.ts` — стартовый список дел.
- `src/lib/` — чистые функции без React (логический день, рутина по времени, очередь).
  Всё здесь покрыто тестами, особенно границы: 05:59, 06:00, 17:59, 18:00, 00:00.
- `src/lib/storage.ts` — ЕДИНСТВЕННОЕ место, которое обращается к localStorage.
  Позже его заменит API, поэтому компоненты работают только через его функции.
- История хранится по логическим датам: `{ [date]: { done: string[], postponed: string[] } }`.
  Сохраняем её с первого дня, даже если в UI она не используется.
- У сохранённых данных есть номер версии формата. При смене структуры — миграция,
  существующие данные не теряются.

## Дизайн
- Mobile-first, основной экран ~360–420px.
- Крупные области нажатия, кнопки «Готово» и «Позже» удобно доставать большим пальцем.
- Светлая и тёмная тема по `prefers-color-scheme`.
- Интерфейс на русском, код и комментарии на английском.

## Как работаем
- Маленькими шагами. Перед заметными изменениями сначала коротко опиши план и дождись ок.
- Не добавляй зависимости без моего согласия.
- После изменений коротко объясни, что поменял и почему, особенно в вёрстке и архитектуре.
- Не коммить без моего подтверждения. Коммиты в стиле Conventional Commits на английском.

## Пока НЕ делаем (бэклог)
Drag-and-drop в редакторе, режимы «мало времени», статистика в UI, теги и взаимозаменяемые дела,
чередование, пауза задач до даты, настройка начала дня, бэкенд и синхронизация.
Не реализовывать и не закладывать заранее, если я не попрошу.
