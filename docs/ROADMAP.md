# Roadmap

Живой план проекта: что уже сделано, что дальше, что в бэклоге.
Решения по продукту принимаются в обсуждении, сюда попадает итог.

## Цель

Приложение на Android-телефоне, которым я пользуюсь каждое утро и вечер:
оно само показывает нужную рутину, крупно выводит текущее дело
и избавляет от вспоминания порядка.

Главное — рабочий инструмент для себя. Портфолио и обучение идут бонусом.

### Ретро

- **План / факт:** закладывалось 3 вечера, код MVP вышел примерно за час, README отдельной сессией.
- **Понравилось:** всё, основная идея работает.
- **Не хватило:** редактирования списка.
- **Раздражало:** дела идут немного не в том порядке. Это правка контента, решается редактором.
- **Лишнего:** не нашлось.
- **Решение:** следующая версия — v1.1, редактор. Новый контент добавляю сама через редактор.

## v1.1 — редактор списка

**Статус:** в работе.

Зачем: менять порядок и состав дел с телефона, без правки кода и деплоя.

### Решения

- Список дел переезжает из кода в localStorage через `storage.ts`.
  `src/data/tasks.ts` становится стартовым списком: загружается, только если сохранённого списка ещё нет.
  Правки в `tasks.ts` после этого на телефон не попадают — всё через редактор.
- У сохранённых данных появляется номер версии формата, чтобы потом спокойно менять структуру
  и переезжать на сервер.
- Существующая история не теряется.
- Редактор — отдельный экран, вход по кнопке-шестерёнке с главного экрана.
- Внутри редактора переключатель «Утро / Вечер». Переносить дело между ними не нужно.
- Изменения сразу действуют на сегодняшнюю очередь, отметки «Готово» и «Позже» сохраняются.
- Удалённое дело остаётся в истории под своим id.

### Шаги

1. [x] Список дел в хранилище: загрузка, сохранение, стартовый список, версия формата. Тесты.
2. [x] Экран редактора: просмотр списка утра/вечера, вход и выход.
3. [ ] Добавить дело (название, обязательное), переименовать, удалить с подтверждением.
4. [ ] Порядок кнопками ↑/↓.
5. [ ] Переключатели «обязательное» и «включено».
6. [ ] Экспорт и импорт всех данных (список + история) в JSON. В быту не нужен,
   это тренировка формата данных перед сервером. Импорт показывает, что будет заменено, и просит подтвердить.
7. [ ] Проверка на телефоне: поправить порядок своих дел через редактор.

### Готово, когда

- Порядок и состав дел меняю с телефона, без кода.
- После перезагрузки и офлайн всё на месте, история за прошлые дни не пропала.
- Можно скачать JSON и восстановить из него.

## Бэклог

- **v1.2:** drag-and-drop в редакторе вместо ↑/↓
- **Замер времени (по желанию):** кнопка «Начать замер» перед рутиной. Каждое «Готово»
  записывает время с предыдущего события (старт / «Готово» / «Позже»), «Позже» время не получает.
  Замер заканчивается, когда рутина пройдена; можно отменить. В обычные дни ничего не меряется.
  На экране «Всё готово» показать, сколько заняла рутина. Данные — новое необязательное поле, без миграции.
- **v2:** режим «мало времени» (может опираться на замеры); варианты дела по уровню (медитация 5 / 10 минут)
- **v3:** статистика, в том числе длительность дел по замерам; отметки дня («выспаться удалось»)
- **v4:** взаимозаменяемые группы дел (сделать одно из группы);
  чередование по дням (растяжка перед сном ↔ йога) — это две разные механики
- Визуал «день/ночь»: солнце утром, луна вечером, тема переключается вместе с рутиной
- Пауза задачи до даты или на X дней
- Настройка начала дня и границы утра/вечера
- Бэкенд и синхронизация (меняется только `storage.ts`)
- Пуш-уведомления: приглашение начать рутину с первым делом
  («Начни со стакана воды», «Пора отходить ко сну, начни с книги»).
  Требуют бэкенда: на статическом хостинге без сервера нет надёжного способа
  показать уведомление в заданное время.
  Открытые вопросы: нужен ли утренний пуш, если время подъёма плавает;
  откуда брать первое дело (сервер знает список после синхронизации, или данные в IndexedDB —
  service worker не видит localStorage).
